# GitHub Discoverability Playbook

This repo is easiest to find when GitHub metadata, README copy, topics,
releases, and contribution docs all describe the same thing: a role-based AI
agent team framework for Flutter product development.

```text
AI agent team framework for Flutter with Codex, Claude Code, Antigravity, Gemini, MCP, role contracts, QA gates, and repo-backed memory.
```

## README Rules

- Keep the first three paragraphs keyword-rich and human-readable.
- Name the concrete tools the repo supports: Codex, Claude Code, Gemini CLI,
  Cursor, Antigravity, MCP, Flutter, Dart, and FVM.
- Keep the first screen focused on what the repo is, who it helps, and what a
  visitor can do next.
- Avoid stuffing keywords into awkward sentences. GitHub search rewards clear
  project language, and humans do too.

## Release And PR Signals

Use searchable release titles when publishing meaningful milestones:

```text
AI Dev Team Flutter v0.1: role-based Flutter agent office
```

Good release notes should mention:

- role contracts and sub-agents
- Flutter quality gates
- supported AI tools
- product/design/architecture/QA/release workflow
- the concrete app or office milestone shipped

PRs should use `.github/PULL_REQUEST_TEMPLATE.md` so the role, scope, files,
test evidence, and risks are visible in GitHub search and review history.

## Maintenance Checklist

Review this file when:

- the repository description changes
- a new AI tool adapter is added
- a new Flutter app or reusable office workflow ships
- a release becomes public-facing
- GitHub topics drift away from the README promise
